# Agent Ready Scorecard

## SBC4

- `Tease:` Most agent-readiness checks help only when they match the site type.
- `Lede:` The highest-value checks are crawler policy, `robots.txt`, sitemap discovery, crawlable/readable content, and honest API/tool discovery when real capabilities exist.
- `Why it matters:`
  - Content sites should not chase API, MCP, OAuth, A2A, or commerce points unless they expose real capabilities.
  - Docs and developer platforms should care more about Markdown, `llms.txt`, OpenAPI, AFDocs, and agent-readable docs.
  - SaaS and API products should treat capability metadata as useful only after the underlying API, tool, and auth flow works safely.
- `Go deeper:` Scores are practical expert-value estimates, not the scanner's pass/fail weighting.

## Practical Priority

1. Start with `robots.txt`, sitemap, crawlable text, and canonical URLs.
2. Split AI crawler policy by search, user-fetch, and training where the vendor supports it.
3. Improve citable content: dates, authorship, direct answers, references, and schema parity.
4. Add Markdown and `llms.txt` when they are cheap to generate from the same content source.
5. Add API, MCP, OAuth, A2A, or commerce metadata only when there is a real capability to expose.
